# B-002: локальная офлайн-студия

Это монтаж из готовых материалов, **не AI-генератор**. Сценарий хранится и
редактируется, но не превращается автоматически в речь. P0/P1 не приняты.

## Запуск
1. Node 24; Python 3.10+ (`python3` в macOS/Linux, `python` в Windows).
   При необходимости укажи путь через `Ywoom_PYTHON` (локальный env, не git).
2. FFmpeg + ffprobe в PATH; FFmpeg с libx264, libass, AAC, PNG/JPEG.
   Установленный шрифт Noto Sans с кириллицей рекомендован. Лицензию конкретной
   сборки FFmpeg проверяет установщик; этот репозиторий бинарники не распространяет.
3. `node apps/api/src/server.ts` (или `npm start`). Для запуска npm install не нужен.
4. Открой `http://127.0.0.1:3000/studio`. Только localhost, не LAN/облачный сервер.
   Не запускай два сервера с одной папкой данных. UI студии пока только русский.

## Быстрая проверка без своих файлов
Нажми **Технический пример (без речи)** → **Сохранить и собрать MP4**.
Будут две диагностические картинки и 30-секундный тихий тестовый тон 440 Hz.
Убавь громкость: это НЕ диктор, НЕ TTS, НЕ доказательство качества P0.
После успеха доступны видео, скачать MP4 и JSON-отчёт с хешами/версией.

## Свой ролик
Создай проект, введи сценарий; пустые строки разделяют 1–6 сцен. Кнопка разбивки
детерминированная, не AI; плашки берутся из первых 160 символов абзаца, их нужно
отредактировать. Подтверди права, добавь изображение каждой сцены и готовую озвучку.
Плашка ≤180 символов, название ≤120, сценарий ≤4000. Сохрани и собери.
Сцены имеют равную длительность, изображения вписываются с полями, без кропа.
MP4: H.264/AAC, 24fps, 720×1280 или 1280×720, 30–60 целых секунд.
Короткая озвучка отклоняется; длинная требует явного согласия на обрезку.
Сценарий не проверяется на соответствие аудио. Качество/смысл оцениваешь вручную.

## Сохранение и ошибки
Проекты, неизменяемые загруженные материалы, версии снимков и результаты находятся
в `.Ywoom-offline/` рядом с корнем проекта; папка gitignored, данные не уходят в облако.
Смена проекта/новый проект предупреждают о несохранённых правках. Конфликт версии
не затирает чужой/параллельный save: перезагрузи проект и перенеси нужные изменения.
Во время рендера можно редактировать: MP4 связан с сохранённым снимком прежней версии.
Отмена останавливает FFmpeg; повтор — явный новый запуск. После перезапуска незавершённые
jobs отмечаются interrupted. Нет автоматического повторного запуска/замены материалов.
Лог ошибки FFmpeg: `.Ywoom-offline/jobs/<id>/ffmpeg.log`; UI показывает ошибку без маскировки.

Лимиты: изображения PNG/JPEG ≤5 MiB, ≤4096×4096; WAV PCM/MP3/M4A AAC ≤12 MiB,
≤120s; без embedded cover/video streams. URL не принимаются. Материалы суммарно
≤100 MiB, ≤20 jobs; один render одновременно, таймаут 300s. Это ограничение числа jobs,
не полная disk quota. Автоочистки нет: останови сервер и архивируй папку целиком, если
лимит достигнут. Не удаляй выборочные assets: проекты/jobs могут на них ссылаться.
Файлы на доверенном локальном диске; нет шифрования, tenant isolation или межпроцессной
блокировки. Не публикуй сервер и не используй для недоверенных пользователей.

## Проверки
Для разработки: `npm ci --ignore-scripts --no-audit --no-fund`, затем `make check`.
Отдельный полный HTTP/FFmpeg путь: `node --test tests/offline.test.ts`.
При отсутствии FFmpeg/ffprobe реальная интеграция явно SKIP, не PASS.
Тесты декодируют реальный MP4, проверяют хеш, Range, снимок версии, 30s portrait /
60s landscape, повтор, ошибки, cancel, сохранение и restart. UI VM-тесты не заменяют
реальный браузер и визуальную/доступностную приёмку. Проверь руками в своём браузере.
Нет новых JS runtime dependencies, платных провайдеров/публичного deploy.
