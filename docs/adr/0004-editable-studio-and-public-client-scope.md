# ADR-0004 — Editable Studio and public client scope
Status: product direction authorized for specification on 2026-10-01; technical tools proposed.

Context: v0.3 late editor UI undermined result-first manual workflow; data assumed video episodes.
Decision: common media-neutral content/editable document contract + specialized timeline/text/canvas;
baseline P2 editors, advanced P5. Manual/batch same pipeline and guards. Three onboarding entrances.
FFmpeg is processing/render tool, not interactive browser editor. New Q-036…042 cover implementation/evidence.
International UI uses prebuilt locale catalogs; no per-screen LLM translator. Coverage independent of voices.
Responsive web P2; Android/iOS required target for all-client public launch Q-049G/P6.
Future JEWEL shell uses scoped module boundary, no new personal modules in first scope.

Consequences: larger explicit P2 scope; re-estimate after prototype, never silently trade reliability for UX.
Static recipe bounded to one result; wide product/ads/carousels/photostudio remain staged branches.
Store readiness may block public release; explicit labeled staged-launch waiver only owner can approve.
Libraries, locale set/order, performance limits and store billing need ADR/preflight, not assumed selected.
Existing evidence-first P0, budget/rights/security invariants and owner gates stay intact.
