# AGENTS.md — правила для любого ИИ-агента в этом репозитории

Ты работаешь в проекте Ywoom + JEWEL Core. Владелец — Oleg (product owner). Он принимает решения, не пишет код.

## 0. Главный закон
Сделай наименьшее изменение, которое закрывает задачу и проходит её критерии приёмки. Никакой архитектуры «на будущее», не описанной в docs.

## 1. Экономия контекста (обязательно)
- НЕ читай весь репозиторий. Порядок: `docs/STATE.md` → текущая задача в `tasks/BACKLOG.md` → файлы из поля `context:` задачи.
- Для поиска используй `rg`/`grep`/`ls`, а не чтение файлов целиком.
- Каждый модуль имеет `README.md` ≤ 60 строк: назначение, публичный API, инварианты. Читай его вместо исходников соседних модулей.
- Стабильные документы (AGENTS.md, docs/*) не переписывай без задачи — это сохраняет prompt cache.
- Логи тестов: выводи только упавшие тесты (`--quiet`, `-x`, `tail -50`).
- Если задача требует > 15 файлов контекста — остановись и предложи её разбить.

## 2. Цикл задачи
1. Прочитай задачу, перечисли критерии приёмки своими словами (3–7 пунктов).
2. Напиши/обнови тесты на критерии (сначала красные).
3. Реализуй.
4. `make check` (lint + typecheck + unit + contract). Всё зелёное.
5. Обнови: module README (если менялся API), `docs/STATE.md`, статус задачи, `docs/adr/` (если принято архитектурное решение).
6. Коммит: `T-XXX: <кратко>`; в теле — что проверено, что не сделано, расходы токенов/денег если известны.
7. Отчёт владельцу: 5–10 строк, без воды.

## 3. Стоп-условия (спроси владельца)
- 3 неудачные попытки починить одно и то же → стоп, отчёт с гипотезами.
- Нужна новая внешняя зависимость/сервис/платный ключ.
- Изменение схемы БД с потерей данных, auth, прав, биллинга, лимитов бюджета, политик безопасности.
- Противоречие между задачей и docs. Не переписывай docs, чтобы оправдать своё решение.

## 4. Запреты
- Не отключай тесты, линтеры, гейты, бюджетные лимиты, чтобы «пройти».
- Не коммить секреты. Только `.env.example`.
- Не вызывай платные генеративные API в тестах — только моки/фикстуры (`PROVIDER_MODE=mock`).
- Не меняй код в `core/policy/` и `core/budget/` без отдельной задачи с меткой `security`.
- **Нет продуктовых дефолтов** (docs/14): не зашивай ниши, персонажей, языки контента и «канал владельца» в код, сиды и миграции. Не делай обходов онбординга.
- Не добавляй зависимости от студийных платформ (Higgsfield и аналоги); студийные функции — только как навыки Ywoom (docs/15).

## 5. Стек и стиль (см. docs/03_ARCHITECTURE.md)
- TypeScript (strict) для web/api/orchestrator; Python 3.12 для media-workers.
- Контракты между модулями — JSON Schema/zod в `packages/contracts`. Любая структура данных между модулями описана там.
- Имена в коде — английские. Комментарии — кратко, по делу.

## 6. Команды
- `make dev` — локальный запуск (docker compose).
- `make check` — все проверки.
- `make eval` — оффлайн-эвалы пайплайна на фикстурах.
