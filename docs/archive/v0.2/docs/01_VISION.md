# 01. Концепция v2

## Одной фразой
Ywoom — система, в которую человек приносит **себя** (знания, желания, время, внешность или персонажа), а получает **работающий канал**: стратегию, серии контента, готовые к публикации ролики/посты, публикацию и рост, который система сама улучшает по данным.

## Что изменилось относительно исходного плана
### Докрутили
1. **Creator Genome вместо «персонажа».** Единая модель пользователя: цели, навыки, время, бюджет, комфорт перед камерой, экспертиза, стиль. Из неё выводятся любые «лица» канала: реальный человек, цифровой двойник (с согласия), вымышленный персонаж, безликий формат. Персонаж — частный случай, а не отдельная сущность (docs/07).
2. **Expert Amplifier.** Подсистема для эксперта, у которого проблема в подаче, а не в пользе: извлекает знания интервью-агентом, упаковывает в форматы, подбирает подачу под его возможности.
3. **Cost Tiers для сцен.** Не каждая секунда — дорогая AI-видеогенерация. Каждая сцена получает уровень: T0 статика+движение камеры, T1 2.5D/параллакс/моушн-графика, T2 Blender-сцена, T3 AI-видео (image-to-video), T4 премиум-модель для «героических» кадров. Главный рычаг себестоимости (docs/10).
4. **Эталоны (Golden Library).** Всё, что сработало (промпт, сцена, хук, монтажный паттерн, обложка), сохраняется как эталон с метриками и переиспользуется. Это и есть «самообучение» без дообучения моделей (docs/08).
5. **Model Router с адаптерами.** Модели — сменные «картриджи». Своё — оркестрация, данные, память, эталоны, оценка качества. Чужое — только вычисления, и всегда заменяемое (docs/06).
6. **Series Bible.** Иерархия Проект → Канал → Серия (формат) → Эпизод → Сцена → Шот. У каждого уровня свой «канон», наследуемый вниз. ИИ не путается между двумя разными сериями одного канала.

### Вырезали (отложили до после первого дохода)
- JEWEL Capital (финансы, инвестиции, недвижимость), Physical Operations, автосоздание бизнесов. Архитектурно место оставлено (плагины-«подразделения»), кода нет.
- Собственные видеомодели и обучение моделей. Сначала данные и эталоны — потом, если окупится, fine-tune open-weight моделей.
- Полный клон редактора Higgsfield. Вместо этого — редактирование «на уровне намерения» (промпт + маски + перегенерация шота) и экспорт таймлайна в DaVinci/Premiere/CapCut через EDL/FCPXML.

## Принципы
1. **Своё ядро, арендованные мышцы.** Любой внешний сервис — за адаптером с контрактом и тестом. Замена провайдера = новый адаптер, а не рефакторинг.
2. **Всё — данные.** План, сцена, промпт, решение владельца, метрика — записи в БД. Это делает систему обучаемой и переносимой на будущие модели (путь к AGI — технический нюанс, а не переделка архитектуры).
3. **Автономность уровнями.** L0–L4 на проект и тип действия (docs/09). Необратимое — только с подтверждением.
4. **Измеряемость.** Каждое улучшение проверяется метрикой. Нет метрики — нет «улучшения».
5. **Dogfooding.** Первый клиент — канал владельца. Продукт выходит на рынок, когда канал растёт.

## North Star метрики MVP
- Время от «регистрация» до первого опубликованного видео: < 60 минут участия человека.
- Себестоимость минуты готового видео (цель по tier-миксу — docs/10).
- Acceptance rate: доля эпизодов, принятых без правок (цель ≥ 70% к M4).
- Удержание аудитории (AVD/APV) и CTR обложек по сериям — растут от эпизода к эпизоду.

## Дополнения v0.2
- **Массовый продукт с первого дня.** Никаких настроек под конкретный канал; владелец — первый обычный пользователь (docs/14).
- **Язык — выбор пользователя** на уровне канала/серии, мультиязычность и дубляж (docs/16).
- **Собственная студия**: камера, кино-студия, эффекты, персонажи, липсинк, монтаж — как версионируемые самоулучшающиеся навыки (docs/15). Никакой зависимости от Higgsfield.
- **Director LLM + прямые API**: режиссёр — топовая LLM через API; исполнители — Blender-воркер и видео-модели с посекундной оплатой (docs/06, docs/10).
