# 03. Архитектура

## Стиль
**Модульный монолит + отдельные воркеры.** Один репозиторий (monorepo), один деплой API, воркеры масштабируются отдельно. Микросервисы — не раньше, чем появится нагрузка.

```
apps/
  web/            Next.js (admin + Director Chat + медиатека)
  api/            Node/TS (Fastify или Hono) — REST + WebSocket
packages/
  contracts/      zod/JSON Schema всех сущностей и команд (единый источник истины)
  core/           домен: projects, bible, episodes, commands, journal
  orchestrator/   JEWEL-lite: графы задач, стейт-машины, ретраи, бюджет
  router/         Model Router + адаптеры провайдеров (docs/06)
  memory/         Genome, эталоны, векторный поиск, кэш
  policy/         автономность, разрешения, лимиты (защищённая зона)
  budget/         сметы, учёт, лимиты (защищённая зона)
workers/
  media/          Python: FFmpeg, монтаж по Timeline JSON, субтитры, рефрейм
  blender/        Python: headless Blender (bpy) — блокинг камер/сцен, рендер
  asr_tts/        Python: транскрипция, выравнивание, TTS-адаптеры
infra/            docker compose, миграции, CI
```

## Инженерный стек (дешёвый старт; это не продуктовый дефолт)
| Слой | Выбор | Почему |
|---|---|---|
| БД | PostgreSQL 16 + pgvector | одна БД для всего: данные, векторы, очередь |
| Очередь | Postgres-очередь (pg-boss / graphile-worker) | без Redis на старте |
| Workflow | стейт-машины в БД + идемпотентные шаги | восстановление после сбоя, без внешнего Temporal |
| Auth | Auth.js / Lucia + magic link | своё, без привязки |
| Файлы | S3-совместимое API (Cloudflare R2 / MinIO) | один интерфейс, нет платы за исходящий трафик у R2 |
| Хостинг | 1 VPS (Hetzner/аналог) + docker compose | фиксированная низкая цена |
| GPU | по запросу (serverless GPU / аренда по часам) | только для open-weight моделей и тяжёлого рендера |
| Монтаж | FFmpeg + собственный Timeline JSON → рендер | без лицензий, полный контроль |
| 3D | Blender headless (bpy) | блокинг камеры, превизуализация, контроль движения |
| CI | GitHub Actions | бесплатно на старте |

## Ключевые архитектурные решения
1. **Contracts-first.** Все структуры между модулями — в `packages/contracts`. Агенты-разработчики читают контракты, а не чужой код → меньше контекста.
2. **Command Journal.** Любое изменение (человек или агент) — команда `{actor, type, payload, parent, cost}` в неизменяемом журнале. Даёт откат, аудит и обучающие данные.
3. **Episode Manifest.** Эпизод целиком описан JSON-манифестом (сцены, шоты, промпты, модели, seeds, аудио, таймлайн). Рендер = чистая функция от манифеста + ассетов. Воспроизводимость и кэш.
4. **Timeline JSON.** Собственный формат монтажа (дорожки видео/аудио/текст/эффекты). Экспортёры: MP4, EDL/FCPXML для внешних редакторов.
5. **Provider Adapters.** Единый интерфейс `generate(request) → job` с возможностями (capabilities) и ценой (docs/06).
6. **Policy/Budget — защищённая зона.** Отдельные тесты, отдельная метка задач, агент не может менять без явного разрешения.

## Storage (стратегия хранения)
- **Hot** (R2/MinIO): рабочие ассеты текущих эпизодов, TTL 30 дней после публикации.
- **Cold / у пользователя**: финальные мастер-файлы и исходники синхронизируются в облако пользователя (хранилище выбирает пользователь в онбординге — `channels.storage_target`; первый адаптер Google Drive, далее Dropbox/OneDrive через тот же `UserStorage`).
- **Всегда у нас**: манифесты, промпты, превью (низкое разрешение), метрики — это мозг системы, они маленькие.
- Перерендер из манифеста возможен, если мастер удалён (кроме недетерминированных генераций — их исходники хранятся до публикации).

## Готовность к будущему (AGI-ready)
- Модели — за роутером; агенты — это конфиги (роль, инструменты, политика), а не код.
- Инструменты доступны через внутренний tool-registry, совместимый с MCP: любую новую модель можно подключить как «исполнителя» без изменения ядра.
- Все знания — в БД в человекочитаемом виде (не в весах модели) → переносимы.
