# 08. Самообучение, эталоны, кэш

«Самообучение» здесь — не дообучение весов, а накопление проверенных данных, которые меняют поведение системы. Это дёшево, прозрачно и переносится на любые будущие модели.

## 4 контура обучения
1. **Контур качества (минуты):** QA-критик → перегенерация шота. Данные: какие промпты/модели проходят QA.
2. **Контур вкуса (часы):** правки и решения владельца → Genome/Bible. Каждое «переделай» с причиной — обучающий пример.
3. **Контур аудитории (дни):** метрики площадки → инсайты («хуки-вопросы дают CTR +X% в серии A») → эксперименты A/B (заголовки/обложки, хуки в разных эпизодах).
4. **Контур системы (недели):** JEWEL анализирует стоимость, сбои, медленные шаги, новые модели → задачи на улучшение кода/промптов (docs/09).

## Golden Library (эталоны)
- Элемент: промпт шота, паттерн сцены, монтажный паттерн, хук, заголовок, обложка.
- Попадает в эталоны при: QA ≥ порога И принят человеком ИЛИ метрики выше медианы серии.
- Используется как few-shot при генерации (поиск по embedding + scope). Эталоны с падающим результатом деградируют (`score` с затуханием).

## Контроль галлюцинаций
- Структурированные выходы (JSON Schema) на каждом шаге — невалидное отклоняется автоматически.
- Факты для образовательного контента — только из базы знаний/источников со ссылками; утверждения без источника помечаются.
- Независимый критик (другая модель, чем исполнитель) для важных шагов.
- Инсайты имеют tier; experimental не меняют стратегию без эксперимента.

## Кэш (много уровней)
1. **Prompt caching** провайдеров: стабильный префикс (система + Bible) в начале, изменчивое в конце.
2. **Generation cache:** `request_hash` → ассет. Одинаковый запрос не оплачивается дважды.
3. **Semantic reuse:** похожий шот (локация, ракурс) — переиспользовать/дорендерить вместо новой генерации.
4. **Asset reuse:** Character Pack, фоны, интро/аутро, звуки серии.
5. **Context packs:** предсобранные компактные сводки Bible/Genome (≤ 1–2 тыс. токенов) вместо полных документов.

## Эксперименты
Одна гипотеза — одна метрика — минимальный объём выборки — авто-итог. Лимит активных экспериментов на канал (настройка канала `max_active_experiments`, системный стартовый предел 2), чтобы не распылять данные.
