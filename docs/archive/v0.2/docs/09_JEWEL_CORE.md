# 09. JEWEL Core — стек агентов и контроль

JEWEL на старте — не «сверхразум», а надёжный диспетчер: задачи, роли, бюджет, журнал, политики. Интеллект — в моделях, надёжность — в JEWEL.

## Два стека агентов
### A. Dev Stack (строит Ywoom) — живёт в IDE/CLI
| Роль | Модель (класс) | Когда |
|---|---|---|
| Architect | сильнейшая модель | начало этапа, ADR, разбиение на задачи |
| Implementer | основная кодинг-модель (оплата по D3: подписка/API/гибрид) | каждая задача |
| Auditor | модель ДРУГОГО вендора | конец этапа, задачи с меткой security, спорные баги |
| Test Writer | дешёвая/быстрая модель | тесты по AC, фикстуры |
| Scout | дешёвая модель + веб | раз в неделю: новые модели/библиотеки |

Правила: Auditor получает требования + diff + результаты тестов (не весь репо) и ищет ошибки, а не подтверждает. Дорогая модель — только когда дешёвая не справилась 2 раза.

### B. Production Stack (работает внутри Ywoom)
Главный — **Director LLM** (топовая модель через API, с prompt caching; docs/06 §Director). Он управляет съёмочной группой из docs/05 и вызывает навыки студии (docs/15), которые работают с Blender-воркером и видео-API. Далее: Strategy Engine + Analyst + Scout моделей + Skill Lab. Конфиги ролей — в БД (`agent_roles`), версионируются, A/B-тестируются.

## Автономность
| Уровень | Значение | Пример в Ywoom |
|---|---|---|
| L0 | наблюдение | анализ метрик, отчёты |
| L1 | советник | предлагает план/правки |
| L2 | исполнитель в рамках | генерирует эпизоды утверждённого плана в бюджете |
| L3 | директор проекта | сам корректирует план серии по данным, публикует |
| L4 | портфель | распределяет бюджет между сериями/каналами |

Политика = `(scope, action, level, limits{usd, count, ttl})`. Всегда требуют человека: изменение бюджетных лимитов, политик, удаление данных, публикация при review_mode=all, использование чужой внешности/голоса, любые платежи.

## Надёжность
- Каждый run: смета → выполнение → отчёт (что сделано, что проверено, стоимость, что не решено).
- Детектор зацикливания: N ретраев / рост стоимости без прогресса → стоп.
- Kill switch вне агентов (env-флаг + админ-кнопка), неизменяемый журнал, бэкапы БД ежедневно.
- Изменения кода агентами — только через ветку + CI + (для защищённых зон) ревью.

## Эволюция JEWEL
- v1 (M0–M2): оркестратор задач Ywoom + бюджет + журнал.
- v2 (M4–M5): Ops Director Ywoom — мониторит сбои/стоимость, создаёт задачи в BACKLOG, запускает Dev Stack в CI на staging.
- v3 (после дохода): подразделения-плагины (Business, Capital, Personal) на том же ядре.
