# 10. Бюджет и экономия

> Цены моделей быстро меняются. Все цифры — ориентиры. Источник правды — `config/pricing.yaml`, его обновляет Model Scout. Начальные цены — docs/research/HIGGSFIELD_EXPRESS_RESEARCH.md §Цены.

## Два разных бюджета
1. **Production** — то, что тратит сам Ywoom на контент. Только API, оплата за фактические единицы. У каждого пользователя — свой бюджет канала, заданный в онбординге.
2. **Development** — то, что тратят кодинг-агенты на построение Ywoom. Способ оплаты — настраиваемый (D3).

## Production: прямые API, посекундная оплата
- Видео-модели — напрямую у вендоров (цена за секунду с учётом разрешения и звука). Агрегатор — только запасной адаптер.
- По сравнению от 23.09.2026 диапазон при 720p — примерно $0.05–0.40 за секунду; рабочий коридор $0.08–0.15.
- **Платим за сгенерированные секунды, а не за оставленные.** Главная метрика — `waste_ratio = seconds_generated / seconds_kept`. Цель ≤ 2.0; модель дороже за секунду, но с меньшим числом дублей, может быть дешевле.

### Cost Ledger (посекундный учёт)
Каждый платный вызов → строка `cost_ledger` (docs/04): провайдер, модель, единица (second/token/image/char), количество, цена единицы, разрешение, звук, сумма, оставлено ли в финале. Дашборд: стоимость по эпизоду, сцене, навыку, модели; waste_ratio; сравнение сметы и факта.

### Director LLM через API
- Топовая модель класса Opus делает только режиссёрскую работу: стратегия, сценарий, раскадровка, выбор навыков, разбор результатов.
- Рутина (парсинг, теги, простые промпты, субтитры) — дешёвая модель через тот же роутер.
- **Prompt caching**: стабильный префикс (роль, каталог навыков, Bible канала, Genome) идёт первым и кэшируется; переменная часть — в конце. Метрика `cache_hit_rate` в `agent_runs`, цель ≥ 70% входных токенов.
- **Batch API** для несрочного (план на месяц, ночной разбор метрик), если провайдер даёт скидку.
- Structured output вместо длинных рассуждений в ответе; лимит выходных токенов на шаг.
- ID модели — в `config/models.yaml`, смена без кода.

### Примерная себестоимость (видео, 720p, коридор $0.08–0.13/с, waste_ratio 2)
| Эпизод | AI-видео (T3/T4) | Сгенерировано | Видео | + Director, TTS, изображения |
|---|---|---|---|---|
| Short 45 с, 60% AI-видео | 27 с | 54 с | $4.3–7.0 | +$0.5–1.5 |
| Short 45 с, 30% AI-видео | 14 с | 28 с | $2.2–3.6 | +$0.5–1.5 |
| Long 10 мин, 15% AI-видео | 90 с | 180 с | $14–23 | +$2–5 |
Итог: tier-микс (T0–T2 бесплатны или почти бесплатны) и waste_ratio важнее выбора модели. Доля AI-видео — настройка канала, система предлагает её исходя из бюджета.

## Development: оплата кодинг-агентов (D3)
Честно о разнице:
- Для **генерации видео** API с посекундной оплатой обычно выгоднее подписок-посредников — согласны.
- Для **написания кода** агентом картина другая: агент читает много контекста, и фиксированная подписка вендора часто даёт больше работы на доллар, чем те же токены по API. API выигрывает при небольшом объёме и хорошем кэше. Проверяется цифрами, а не мнением.
- Подписка кодинг-агента не заменяет API в production: бэкенд Ywoom всегда ходит в API.

Решение принимается по данным: в M0 две недели пишем `agent_runs` с токенами и стоимостью (или эквивалентом для подписки) → сравниваем стоимость закрытой задачи → выбираем. Режим задаётся в `config/dev_billing.yaml`: `subscription | api | hybrid`, с жёстким месячным потолком (D10).

## Распределение ~$200/мес на этапе строительства
| Статья | M0–M2 | M3+ |
|---|---|---|
| Разработка (кодинг-агент + аудитор, D3) | 150–170 | 90–110 |
| VPS + хранилище + домен | 10–15 | 15 |
| Director LLM в production (API, с кэшем) | 0–5 | 15–25 |
| Генерации (видео/изобр./аудио, посекундно) | 0–10 (моки) | 40–60 |
| Резерв | 10 | 10 |
M0–M2 идут на моках, поэтому почти весь бюджет — в разработку. С M3 владелец задаёт бюджет своего канала в онбординге, как любой пользователь. При $50 на генерации это примерно 8–12 Shorts + 1 Long в месяц при умеренной доле AI-видео.

## Экономия контекста разработки
1. AGENTS.md + module README вместо чтения кода.
2. Задачи ≤ 1 дня работы, с полем `context:`.
3. Стабильный префикс (правила, контракты) → попадание в кэш.
4. Английский в спецификациях и коде (T-000).
5. Тесты выводят только ошибки.
6. Свежая сессия на каждую задачу; состояние — в `docs/STATE.md`.
7. Дешёвая модель для рутины; дорогая — по эскалации.

## Экономия генераций
1. **Tier-микс** (docs/05) — главный рычаг.
2. **Сначала превью**: 480p / короткая длительность / дешёвая модель → утверждение → финал.
3. **Беззвучные режимы**, если звук всё равно сводится отдельно.
4. **Кэш и переиспользование** (docs/08); `request_hash` исключает повторную оплату.
5. **Роутер по цене за принятую секунду**, а не по прайсу.
6. **Смета до запуска**, стоп при превышении.
7. Позже — open-weight модели (напр. LTX, MiniMax H3) на арендованном GPU, когда объём это оправдывает.

## Unit-экономика (считается автоматически)
`cost_per_finished_minute`, `cost_per_accepted_episode`, `waste_ratio`, `cache_hit_rate`, `revenue_per_episode`. Решения о масштабе — только по этим числам.
