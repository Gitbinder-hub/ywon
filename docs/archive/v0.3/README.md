# Ywoom + JEWEL — Spec Pack v0.3

**Амбициозная цель сохранена. Реализация — через измеримые этапы.**
Версия: 0.3.0 · 01.10.2026 · владелец: Oleg.

Это пакет требований, плана и передачи работы между агентами, **не готовое приложение**.
Архив v0.2 сохранён побайтно в `docs/archive/v0.2/`. Он исторический, не источник активных требований.
Ни код продукта, ни реальная стоимость, ни качество видео этим пакетом не подтверждены.

## Начать за 5 минут
1. Распаковать содержимое этой папки в корень репозитория. Сделать отдельную ветку и просмотреть diff, если в репозитории уже есть код; не перезаписывать его без проверки.
2. Выполнить `python3 scripts/project.py validate`, затем `python3 scripts/project.py status` и `python3 scripts/project.py next`.
3. Прочитать `AGENTS.md`, `docs/STATE.md`, `docs/17_MASTER_PLAN.md`, затем только контекст выбранной задачи.
4. Первая задача — **Q-001: владелец принимает v0.3 и разрешает бюджет технического эксперимента**. Платных вызовов до этого нет.
5. Агент берёт готовую задачу через `project.py start`, реализует, проверяет и сдаёт через `submit`. Статус REVIEW — не DONE. DONE назначается только после приёмки владельцем.

## Ближайшая последовательность
P0: реальный технический эксперимент без полного приложения →
P1: минимальное надёжное ядро и изоляция пользователей →
P2: первый пользовательский цикл 30–60 с с ручным одобрением →
P3: повторяемость и внешние пользователи →
P4: аналитика и контролируемое улучшение →
P5: выбранные студийные расширения →
P6: безопасный рост и эксплуатация.
Это гейты, не обещанные календарные сроки. Переходы утверждает владелец по доказательствам.

## Карта пакета
- `docs/01…16`: активные предметные спецификации, v0.3.
- `docs/17_MASTER_PLAN.md`: вся цель, этапы, будущие возможности, без потери амбиций.
- `docs/18_AGENT_HANDOFF.md`: передача контекста, сессии, остановки, приёмка.
- `docs/19_VALIDATION_PROTOCOL.md`: реальный эксперимент и критерии качества.
- `docs/20_SECURITY_AND_OPERATIONS.md`: секреты, изоляция, CI, деплой и защита агентов.
- `docs/21_SPEC_REVIEW.md`: замечания аудита → принятые изменения/остаточные риски.
- `docs/22_UPGRADE_GUIDE.md`: перенос из v0.2 и начало работы в IDE.
- `tasks/project.json`: единственный источник статусов задач/зависимостей/приёмки.
- `tasks/features.json`: полный реестр продуктовых возможностей; статусы вычисляются из задач.
- `tasks/BACKLOG.md`, `docs/STATE.md`: генерируемые представления, не редактировать вручную.
- `handoffs/`: отчёты сдачи с доказательствами; `reports/`: проверочные материалы.
- `scripts/project.py`: локальная проверка/ведение плана; не запускает агентов, API и деплой.
- `prompts/`: старт, продолжение, реализация, аудит и передача — для любого агента.

## Модель-независимая работа
Cursor, Claude Code, Codex или другая среда читают одни и те же файлы.
`CLAUDE.md` дублирует правила `AGENTS.md`; это проверяется. API-модель выбирается конфигурацией,
а не зашивается в план. Предпочтение владельца — сильные модели класса GPT Astra / Opus 5.5;
точный доступный ID, цена и пригодность проверяются перед использованием.
Для Cursor добавлено правило `.cursor/rules/Ywoom.mdc`. Оно не заменяет AGENTS.md.

## Локальные проверки
Python 3.10+ без сторонних зависимостей:
```
python3 scripts/project.py validate
python3 -m unittest discover -s tests_spec -v
python3 scripts/project.py status
python3 scripts/project.py next
```
`make spec-check` — то же. Эти тесты проверяют **пакет и процесс**, не качество AI-видео.
Автоматизация передачи = устойчивое состояние в git, а не тайный автономный запуск новых агентов.
