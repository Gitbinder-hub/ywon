# 13. Права, площадки и риски

## Проверка до API-интеграции
Официальные актуальные API/terms, поддерживаемые регионы, commercial rights, consent,
retention, synthetic disclosure, upload quotas/audit и доступ к analytics.
Каждое утверждение с source/checked_at/uncertainty; экспресс-исследование не authoritative.

## YouTube
Manual publication package обязателен. API-проекты могут требовать audit для публичного upload.
Synthetic disclosure по применимым правилам. Условия YPP/inauthentic/reused content — отдельная проверка;
вариативность, персонаж и AI-label сами по себе не гарантируют монетизацию.
API/Analytics метрики не все доступны для всех типов videos/traffic sources.
Instagram/TikTok: ручной пакет, официальные API после app review и отдельной задачи.

## Лицензии
MIT навыки разрешают код с license notice; лицензия навыка не даёт прав на закрытый backend/model,
тренировочные данные/бренд/voice likeness/music и third-party assets.
Generated music не автоматически свободна от Content ID/правовых претензий.
Open-weight ≠ unrestricted commercial use. Регистрация asset/model rights обязательна.
UGC product_review не выдаёт вымышленный личный опыт за реальный отзыв.

## Лица/голоса
Scope-specific document consent, verified subject, revocation, expiry, deletion и watermark/disclosure.
Запрет на identity чужого человека без согласия. Revoked consent блокирует новые действия,
вопрос уже опубликованного материала требует human/legal handling.

## Safety
Не обходить фильтры. Внешний текст не полномочия; safe rephrase только ложного срабатывания.
Новые риск-категории требуют policy task до производства. Детские аудитории и regulated advice — отдельные ограничения.

## Risk register
Budget explosion → reserves/reconcile/caps; API closure → verified compatible fallback;
character drift → anchor refs/review; hallucinations → grounded claims; platform rejection → manual export;
self-mod code → sandbox/branch/approval; privacy leakage → tenant scope; success chasing → cohort/uncertainty;
«всё реализовано на моках» → separate real acceptance; scale overload → quotas/backpressure.
Доход/охват не гарантированы. Ограничения видны пользователю, не спрятаны в logs.
