## 2. AC2 — quality / critical failure / cost / human-time envelope + число запусков

### 2.1 Quality rubric (human reviewer, VLM только advisory)

Шкала per run: usable as-is / minor changes / major changes / reject + minutes и причина. Критический провал = reject независимо от баллов.

Technical:
- Файл декодируется ffprobe/ffmpeg, h264 1280x720 + aac, duration 30±2с (строго, оба ограничения), звук есть, нет непреднамеренных чёрных/тихих сегментов.
- Субтитры (если есть) синхронизированы; -shortest не обрезает narration (narration.wav vs result.mp4).

Meaning:
- Скрипт покрывает brief, утверждения корректны, нет выдуманных критических советов.
- 3 сцены соответствуют сценарию (image prompts из script).

Perception:
- Речь разборчива (ru, Kore), текст читаем, нет severe artifacts, визуальное разнообразие уместно.

Rights:
- Disclosure synthetic voice, лицензии/consent указаны, нет чужого IP/ликнесса.

Калибровка: пороги именованы и привязаны к методу (ffprobe, human blind rubric).

### 2.2 Critical failures (любой = reject)

1. not_decodeable — ffprobe не открывает.
2. duration_out_of_contract — вне 28-32с при strict.
3. silent_or_black — тишина/чёрный >1с или отсутствие дорожки.
4. narration_truncated — wav обрезан -shortest / hash mismatch.
5. script_hallucination_critical — выдуманный критический совет.
6. rights_violation — чужой бренд/лицо/копирайт без разрешения.
7. audio_unintelligible — речь неразборчива носителю ru.
8. hash_mismatch_or_tamper — mp4/inputHash/manifest не совпадают.

VLM feedback отдельно, не заменяет human. Golden set frozen/versioned; holdout не тюнится.

## 3. AC3 — схема run report (все попытки, rejected outputs, small-sample)

### 3.1 Report per run + aggregate

Per-run: reports/eval/P0-00X.json + outputs/<runId>/manifest.json|script.json|result.mp4|narration.wav (hash/sha256/bytes/duration/ffprobe).

Поля per run: runId, topic, briefHash, models {text,image,tts}, prompts {script,image[1..3],tts}, assetHashes, mp4 {path,sha256,bytes,durationSec,codec}, inputHash, durationContract {mode strict toleranceSec 2 fullNarrationRequired true}, cost {baselineMicros, reserveMicros, capMicros, actualBilledMicros, invoiceStatus}, attempts [{n,status,error,billedMicros,startedAt,endedAt}], rejectedOutputs [], humanReview {verdict usable|minor|major|reject, minutes, reason, reviewer, criticalFailure}, accepted bool.

Aggregate reports/P0_EVAL_AGGREGATE_2026-10-XX.md:
- Таблица 9 строк: runId / topic / accepted? / rubric / criticalFailure / duration / attempts / cost / minutes / hashes.
- Aggregates: acceptance_rate = accepted/9, pass per rubric dimension, cost min/p50/max, total billed vs baseline, waste_ratio, reuse, human minutes total/p50, recurring defects.
- Все неудачи и отклонённые outputs перечислены; нельзя выбирать 3 лучших из 20.
- Small-sample limits явно: n=9 screening, не статистика; go не доказывает рыночный успех.
- Spec threshold не считается выполненным без реальных данных. Версии/attempts/commands/limits зафиксированы.

### 3.2 Cost/human-time в отчёте

- Baseline (frozen) vs latest approved vs actual billed (append-only) — все три видны (COST_VISIBILITY).
- Per item/attempt/provider/localization breakdown; unknown никогда 0.
- B/R/C initial и amendments отдельно; reserved отдельно, не суммируется дважды.
- Human minutes отдельно от model cost.
