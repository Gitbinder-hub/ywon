## 1. Рекомендуемый UX
- По умолчанию микрофон выключен. Кнопка / горячая клавиша открывает разговор. Опционально один локальный вызов по имени открывает ту же сессию; не повторять его в каждом сообщении.
- В активном окне можно задавать уточнения, перебивать, менять задачу. Видимые states: микрофон выключен / слушает / думает / говорит / требуется подтверждение; отдельная индикация передачи аудио в облако и background jobs.
- Pilot defaults: 45 секунд без направленного обращения → закончить разговор; максимум 5 минут на одну сессию. Configurable bounds in controller: idle 1–120 секунд, whole session idle…15 минут. Это инженерные ограничения, не измеренные UX оптимумы и не денежный лимит. Assistant output/background chatter не продлевают окно.
- «Это не тебе», «спи», «закончи разговор» закрывают сессию, отменяют текущую генерацию, очищают буфер воспроизведения и несданный proposal. «Выключи микрофон» / «не слушай» дополнительно запрещают голосовую повторную активацию до физического действия. Кнопка mute доступна всегда; голосовой stop не единственный выключатель.
- Завершение разговора НЕ отменяет уже submitted jobs, не откатывает файлы/покупки и не обнуляет liabilities. Отдельная кнопка остановки задач обращается к существующему core recovery/stop contract.
- Никакого camera/gaze по умолчанию. Optional accessibility push-to-talk и text input остаются полноценными альтернативами.

## 2. Честная граница определения адресата
Без получения звука невозможно узнать, кому адресована фраза. Wake detector тоже слушает: optional armed mode только локально, с отдельным согласием и индикатором; closed/muted не подразумевает скрытый cloud stream. Распознать все семейные разговоры без ошибок не обещать.
VAD/semantic VAD определяют речь и завершение реплики, НЕ доказывают адресата, владельца или permission. Speaker embedding/voiceprint может улучшать UX лишь после отдельного согласия/retention policy; голос не единственный authorizer. TV, запись голоса, близкий человек, речь в наушниках и synthetic audio входят в attack/false activation matrix.
Future capture/classifier adapter выдаёт owner-directed / background / uncertain + echo flag. Это UX label недоверенного аудио, не security credential. Background/uncertain/echo не вызывают модель, не прерывают ответ, не запускают tools и не продлевают idle window. При uncertain допускается отдельный визуальный запрос внимания, но не платный бесконечный переспрос. B-054 tests используют вручную заданные labels: это НЕ доказательство точности classifier.

## 3. Duplex и прерывание
OS microphone/speaker → local AEC/noise suppression/VAD → addressability adapter → VoiceSession → provider transport / same Architect core → audio playback. Audio devices, permission and supported capabilities are OS-adapter responsibilities.
Directed speech onset calls beginSpeech before ASR final text: cancel response + flush playback, then final recognised utterance starts a fresh response. Late audio/model/tool callbacks require exact session/response IDs; duplicate turns/chunks discarded; ended response cannot append playback. Interrupted proposals discarded. Finished model output alone does not authorise execution.
Capture/playback adapter MUST execute returned effects, schedule tick() while idle, enforce bounded queues/frame sizes, stop and clean resources in finally on exception/disconnect/permission loss/suspend. The pure controller cannot physically stop a microphone. Transport failure → muted/closed cue, no implicit reopen/reconnect or regenerated paid reply. Clear queued microphone frames; already transmitted audio cannot be withdrawn. Provider-side cancellation/usage may arrive late and must be reconciled.
CPU target: one capture stream / one playback / bounded buffers; no large local LLM or GPU requirement. STT/TTS route selectable behind versioned interface. Local small-model route only after actual CPU/RAM/latency/accuracy benchmark on owner's i5/12GB. Do not add Docker/WSL as required Windows pilot dependencies or advertise realtime from tests without audio.

## 4. Речь → intent, НЕ полномочие
Transcript is untrusted input, never raw shell, install instruction, local grant, policy override, payment or publish consent. Voice can propose bounded typed actions; core separately validates current permissions, operation identity, budget, destination and actual user confirmation/delegation. Background «да» cannot approve money/delete/install/send/grant/publish. Pilot proposal supports only read-only file inventory request; it cannot run anything.
A proposal carries executionAllowed=false and requiresLocalGrant=true. Physical UI/core separately creates the existing pinned task and signed dispatch. No new voice-only executor/ledger. A signed message from the paired server in future also needs current local device grants: signature alone is not blanket access. Browser/repository/spoken instructions do not become trust roots.
Factory and Companion reuse mission/outcome/recovery protocols. Voice conversation state is transient UX state, not another task state machine. Audio/transcript private memory is NOT shared between runtimes by default.

## 5. Privacy, economics и доступность
Raw audio not persisted by default; no background cloud streaming outside an active explicitly enabled session. Transcript/action previews shown locally; logs IDs/latencies/redacted error codes, not raw speech. Explicit separate consent for recordings/voiceprints, encryption, retention/delete and destination; no seed/passphrase capture/persistence. Account/provider permissions and local physical mute remain independent.
Before paid voice transport, obtain explicit session/day cap and approved provider route; reserve estimated liability through existing budget semantics, meter audio/text/output+cancelled responses+tools and show actual/unknown usage. Session timeout is NOT a hard spend cap. Unknown usage pauses new paid turns pending reconciliation; no blind retries/fallback to another paid model. Current block makes zero provider calls and does not choose a hidden monetary allowance.
Windows10/11 first, builds and lifecycle recorded separately; devices/permissions/AEC/sleep and real audio acceptance on each. Linux/macOS future retain same session/intent schema, OS-specific microphone/privacy adapters and installer requirements; no common-core change to expand tools. Keyboard/text always supported; visual indicator plus optional sound cue, accessible mute/confirmation controls.
