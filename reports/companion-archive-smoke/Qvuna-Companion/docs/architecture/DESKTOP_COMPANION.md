# Desktop Companion / Домовой — отсоединяемая среда Ywon

Нормативное дополнение A-20261005; проектирование, не implemented runtime. Общие Mission/Decision/Capability/Evidence и money/recovery semantics принадлежат ARCHITECT_FOUNDATION.md и предметным economics/production docs. Здесь только desktop-specific boundary. Implementation transitions: docs/governance/IMPLEMENTATION_TRANSITIONS.md.

## 1. Один core, два исполнения
Cloud control plane → versioned module protocol → Factory workers / Desktop Companion. Shared contracts/planning/skills используют одну canonical реализацию; OS adapters не переопределяют states, authorizers или budget rules. Один authoritative owner каждой операции. Общий код можно поставлять клиенту, но authoritative account/tenant/policy/paid budget остаются серверными.
Companion components: lightweight user-session runner; OS adapters; local SQLite journal/artifact index; minimal tray/launcher/control UI; outbound transport. Proposed package boundaries: packages/companion-protocol, apps/desktop-companion, workers/desktop; это target paths, не существующая реализация. Не перекладывать весь Factory/SaaS на ноутбук.
Uninstall/revoke/disconnect затрагивает только этот device scope. Cloud continues independent work; jobs requiring this device wait/expire/cancel as declared. Factory review/export не зависят от Companion availability. Server unavailable: разрешены только заранее выданные bounded local grants; запрещены новые paid/external commitments.

## 2. OS rollout и честная совместимость
| Target | Первый scope | Release evidence |
|---|---|---|
| Windows 10 x64 | Первый owner pilot, конкретные builds/dependencies записать | Install/start/pair/files/browser/stop/sleep-resume/uninstall на реальной OS |
| Windows 11 x64 | Та же contract family, отдельный target | Повторить matrix, не вывести PASS из Windows 10 |
| Linux | После Windows pilot; selected distro/session/architecture | Distro/version; X11/Wayland/permissions; real device checks |
| macOS / MacBook | После Windows pilot; explicit Intel/Apple Silicon targets | TCC Accessibility/Screen Recording, signing/notarization, architecture checks |
Архитектурная переносимость ≠ одинаковый набор tools. Capability manifest объявляет OS/build/architecture/version, GUI/session prerequisites и supported actions. Missing accessibility/permission → unsupported/needs_user, не скрытый fallback. Устройства на unsupported или непатченной OS не получают обещание безопасного public use; перед secrets/production подтвердить vendor lifecycle/patch status. Windows 10 pilot не обещает general public support всех исторических builds.
Первый ориентир: i5-7200U, 12 GB RAM, GeForce 940MX, SSD 238 GB. Это user-reported profile, не benchmark и не free disk. One active browser executor; bounded tabs/CPU/RAM/disk; cloud heavy generation. Native runner first, Docker/WSL/large local LLM не обязательные dependencies. OS-independent core; Windows UI Automation, Linux/macOS equivalents за platform adapters. GUI в интерактивной user session, не Session-0 SYSTEM service. Нужен portable configurable Python executable, preflight versions/paths/UTF-8/process exit codes; no hardcoded python3/POSIX shell assumptions.

## 3. Pairing, export и доставка клиента
Pilot: inspectable package + manifest/hash из доверенного канала, explicit local start; не обходить OS warnings. Public target: signed installer/update metadata, dependency provenance/SBOM, release checks, staged update/rollback; macOS notarization где требуется. Unsigned pilot не маркировать public production distribution. Wrapper (например Tauri) выбирается отдельным packaging spike, не заставляет core зависеть от UI framework.
Device-generated keypair; короткоживущий одноразовый pairing challenge. Authenticated web user подтверждает точное device/owner/workspace и requested scopes; server binds key and device record. QR содержит только verification URL/challenge, не refresh/access token или seed. Limited poll/backoff, code expiry/replay/rate-limit; display binding details to prevent wrong-device approval. Credentials stored in OS credential store; tokens scoped/short-lived, rotate/revoke, server validates device binding. Clipboard/chat/log/export никогда не secret transport.
No inbound internet port, no direct Postgres credentials on laptop. HTTPS outbound long polling first; WebSocket optional after evidence. Authenticated local control socket or loopback with origin/CSRF protection; random websites cannot command runner.
Config export/import has schema/version/hash, skills refs, compatible settings, provenance/privacy classification. No active tokens/cookies/API keys/approvals by default. Private memory export optional, minimised/encrypted with user purpose and retention; new device must pair and obtain fresh grants. Migration does not clone live operation ownership.

## 4. Conceptual protocol v1 (typed schemas implemented later)
| Contract | Required fields / invariant |
|---|---|
| DeviceRegistration | device_id, workspace/user binding, public_key, OS/build/arch, runner/protocol versions, capabilities, observed_at |
| DeviceGrant | grant_id/version, actor/device/workspace, purposes/actions/resources, budget refs, expiry/revocation, offline policy; authenticated binding |
| TaskEnvelope | mission/task/operation IDs, revision/hash, module, required skill/version, inputs/artifact refs, outcome contract, grants, deadline, bounded costs, allowed offline actions |
| Lease | operation/device, monotonic fencing_token, expiry; stale owner denied server commits |
| Progress/Result | operation/attempt, pinned revisions, monotonic event sequence, evidence/artifact hashes, status, cost/unknown liabilities; no caller-invented success |
| Stop/Revocation | scope/reason/effective version, ack; stop new affected actions, preserve reconciliation |
Strict bounded inputs, tenant consistency, trust/source separation. OS capability advertisement does not authorise actions. Local journal is execution evidence, never authoritative financial ledger. General non-media tasks have TaskOutcome contract; do not fake scene/episode/generation records. Existing GenerationUnit remains authoritative for content; research/dev budgets separate, no money reset through device or skill version.
Queue: issued→accepted→running→verifying→succeeded, with paused/needs_user/failed/cancelled/reconciling. Mapping to existing mission/operation state machine explicit; separate device transport states are not a rival mission state. Persist intent before side effect; store receipt/external ID; result reviewed by declared verifier before accepted completion. Event replay exact/idempotent, duplicate delivery not new action.
Lease expiry != safe re-execution. Fencing prevents stale server writes, cannot undo a remote browser click. If external result unknown, freeze affected operation and reconcile before reassignment. Provider idempotency contract preferred; otherwise human verification/compensation, no exactly-once claim. Control-plane grants/reservations pinned; effective checks at dispatch and just before irreversible action.

## 5. Disconnect, suspend и update
Checkpoint before sleep when possible; crash recovery also works without clean checkpoint. Persist IDs, pinned snapshots and sequence before reporting. Heartbeats bounded; no constant LLM polling. Wake resumes by IDs and current grants; queued revoked/obsolete work denied. Cloud tasks run during sleep only without local-only inputs/permissions; selective upload requires consent and artifact checks.
Offline grants have finite time/actions/compute, not permission to spend from stale shared balances. No new external submit offline unless explicitly allowed with independently enforceable limits and reconciliation contract; first pilot denies it. Network reconnect drains events, not duplicate commands. Revocation while disconnected cannot be instantaneous: bounded grant TTL and local kill switch; disclose this limitation.
Updates drain/checkpoint jobs, keep active missions pinned, check protocol/storage migrations/backups, preserve downgrade rules and current revocations. Upgrade cannot widen scopes. Bad signature, incompatible schema or rollback needing incompatible DB → stop/report, not discard journal.

## 6. Access levels and trust
Read-only approved folders first; staged writes to designated workspace; browser/account/apps only explicit device grants. Separate per-tool principal/resource allowlists, path canonicalization and symlink/junction/reparse-point escape checks; Windows case/UNC/network shares tested. Default no admin/SYSTEM/raw shell/unrestricted package installation. User can later grant specific stronger actions, not invisible blanket elevation.
Research code in separate restricted sandbox/process/account, no production secrets/browser sessions. Windows 10 Home may lack optional sandbox features: choose supported isolation or disable arbitrary research execution. Working-folder separation alone is not a security sandbox. Full-admin agent can modify its own local guards: do not promise tamper-proof local enforcement; server money/tenant authorisation and OS isolation are independent boundaries.
Secrets passed via narrow brokers/ref IDs, redacted logs. Browser page/repository/skill content is data, never instruction authority. Pause money/contracts/delete/publish/new install/security changes unless explicit action-bound delegation. Official social API publication remains Factory's separately approved adapter; browser publication not pilot requirement. No bypass account protections, platform limits or program scope.

## 7. Shared experience without shared private memory
Learning loop uses EVOLUTION_AND_LAB.md. ImprovementPackage: id/version, origin runtime+OS+source commit, problem/evidence+counterevidence, candidate recipe/tool hash, input/output schemas, deps/license, required grants, supported targets, measured cost/quality/limitations, holdout refs, migration/rollback and privacy class.
Sanitize before export; no private client/local files, credentials or personal facts bundled implicitly. Destination independently checks contracts/permissions/OS, tests/holdout/review, then canary activation. Source approval is not destination approval. Learning recipes != online weight training; weights remain gated future scope. Research attempts do not silently override the paid content stop-before-third rule.
Shared lab may derive sellable tool candidates; commercial export requires IP/dependency/security/support review and separate release gate, never automatic publication of user-specific code. Scenario-specific requirements: docs/learning/COMPANION_SCENARIOS.md.

## 8. Pilot and public acceptance
First pilot: pairing/approved folder→one deterministic task→checked artifact→server report→sleep/crash recovery→revoke/stop; no paid APIs, outbound messages, purchases, wallet signing or automatic publishing. Mock transport proves only mechanics; paired staging service/real Windows evidence required before calling pilot connected.
Windows 10/11 test targets recorded separately; one tested OS may yield limited pilot only, not both-platform PASS. Common contract fixtures reused by Factory and Companion; real OS GUI checks distinct. Test replay, simultaneous owners, expired grant, offline revocation TTL, wrong tenant, junction escape, untrusted instruction, interrupted upload, disk full, update recovery and unknown external result. Public signing/distribution/multi-user hardening follow transitions, never inferred from pilot.
